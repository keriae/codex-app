## Save and recovery behavior

Text edits autosave after three seconds; **⌘S** saves immediately. **⌘W** saves and closes the active workspace file tab. Failed saves keep the tab and its draft open. Disk conflicts offer using disk content or retaining the local edit against the updated base. Selecting Files after inspecting a diff returns to the selected file instead of leaving the diff displayed.

Per-chat tabs and dirty drafts are stored under the replica's independent desktop profile. Switching away or hiding the workspace retains its document store. On application restart, validated project paths are restored and read again; recovered text is kept when disk contents differ and a conflict is shown. Profile corruption cannot create tabs outside the granted project. Restored drafts are not silently discarded.

If a restored text file has become an image, the recovered editing baseline and draft remain available with a type-change error; native save continues to validate the actual disk type. A pending or failed initial read cannot silently close or replace a restored preview draft. Failed initial reads expose the recovered text in the editor with the disk error, so it can be inspected or exported using Save as. Undoing to the old baseline during an in-flight save still persists the current text, and closing waits for that write before saving any resulting difference. Failed pending writes keep the tab open and preserve that baseline-equivalent undo, including when a sync failure follows a partial disk write. Disk conflicts remain dirty until explicitly resolved, so persistence cannot discard their text. These branches are covered by actual document-store regression tests, including a watcher read overtaking the startup read and a baseline-equivalent recovered undo.

The native save service is a desktop operation, as in the installed client. It validates the root grant, canonical target, UTF-8 text and size, opens a regular file without following a final symlink, compares the expected disk contents, rechecks identity and modification metadata, then writes, truncates and syncs the opened file while preserving its mode. It reports errors and never overwrites a known disk conflict. As with the original optimistic disk-version contract, another uncooperative writer racing the final metadata check is outside its atomicity guarantees.
